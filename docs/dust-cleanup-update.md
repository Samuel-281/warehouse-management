# Web 端涤尘更新说明

## 目标

本轮更新收口数据一致性、大数据性能、异常维护能力和前端结构。更新仅在本地开发与测试环境完成，不包含 GitHub 推送或服务器部署。

## 主要变化

1. 库存增减改为数据库原子更新，并增加库存数量不得为负的数据库约束。
2. 单次业务提交最多处理 500 个条码；出库、销售退回和终端退换货使用批量数据库操作。
3. 单据和库存查询使用服务端分页；完整条码可在全库精确查询单据和当前档案。
4. 单据由物理删除改为有原因的撤销；条码发生后续流转时拒绝整单撤销。
5. 新增条码更正、货物核销、受限错误档案删除和人工库存修正。
6. 密码使用 scrypt；旧明文密码在首次成功登录后自动升级。
7. 生产界面移除演示数据和 `localStorage` 库存回退，数据库故障时显示明确错误状态。
8. 主前端拆分为查询页面、公共 UI、反馈弹窗、API 客户端和扫码表单模块。
9. 入库、出库和销售退回支持 `clientRequestId` 防重复提交；相同请求重试返回首次结果，不会重复改变库存。
10. 登录用户可修改自己的密码；超级管理员可编辑、启停账号和重置其他账号密码，系统始终保留至少一个启用的超级管理员。
11. 系统维护增加只读一致性检查，核对库存余额、数量流水、条码归属、最后流转和作废单据；历史迁移缺少流水基线仅作为提示。

## 验证命令

在 `warehouse-web/` 目录执行：

```bash
npm run lint
npm run build
npm run prisma:validate
npm run test:integration
npm run db:cleanup-runtime
```

`db:cleanup-runtime` 用于删除超过 30 天的防重复请求记录和过期登录会话，生产环境建议每日执行一次。

集成测试会自动创建或重建本机 `warehouse_management_test` 数据库。测试脚本只接受 `localhost`、`127.0.0.1` 或 `::1`，且数据库名称必须以 `_test` 结尾。

## 大数据压测

在独立测试数据库中生成 100,000 个可追踪条码：

```bash
DATABASE_URL="本机测试数据库连接" npm run db:seed-stress -- \
  --count=100000 \
  --transfer=50000 \
  --sales-outbound=50000 \
  --sales-return=10000 \
  --terminal-return=5000 \
  --batch-size=500 \
  --prefix=DUST100K

DATABASE_URL="本机测试数据库连接" npm run db:benchmark -- --barcode=DUST100K000001
```

2026-07-10 本机结果：

| 项目 | 结果 |
| --- | ---: |
| 写入 100,000 条压测数据 | 约 8.1 秒 |
| 首页库存摘要 | 142 ms |
| 库存第一页 | 21 ms |
| 单据第一页 | 133 ms |
| 完整条码库存查询 | 7 ms |
| 完整条码单据查询 | 57 ms |
| 500 条批量出库集成测试 | 约 301 ms |

不同电脑和数据库负载会影响绝对耗时。验收门槛为 500 条提交低于 5 秒、完整条码查询低于 500 ms。

## 已知工具链提示

1. `npm audit --omit=dev` 当前会报告 Prisma CLI 间接依赖 Hono 的 1 个高危和 3 个中危告警。该依赖不处理网站业务请求；自动强制修复会把 Prisma 7 降级到 Prisma 6，因此本轮不执行破坏性降级，等待 Prisma 兼容更新。
2. 集成测试运行时，Prisma PostgreSQL adapter 会输出一条 `pg@9` 兼容性弃用提示。当前测试和事务行为正常；升级 adapter/pg 前需重新执行并发与事务测试。

## 部署注意

本轮新增两项 Prisma migration。未来部署时必须先备份生产数据库，再执行 `npm run db:deploy`。不要在生产数据库运行集成测试、`db:seed-stress` 或测试库重建脚本。
