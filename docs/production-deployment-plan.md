# 仓库货物管理系统部署方案

## 1. 当前决策

1.0 版本采用“阿里云 ECS 同机部署”：

1. Next.js 网站和 API 运行在 ECS。
2. PostgreSQL 数据库也运行在同一台 ECS。
3. Nginx 对外提供 `80/443` 访问，并反向代理到本机 `127.0.0.1:3000`。
4. PostgreSQL 只允许本机连接，不开放公网 `5432`。
5. 使用宝塔 Linux 面板辅助维护 Node.js、Nginx、PostgreSQL 和计划任务。

该方案比 ECS + RDS 成本低，也比 NAS 暴露数据库更简单，适合 10 人左右的小团队试运行和轻量正式使用。

## 2. 推荐配置

| 项目 | 建议 |
| --- | --- |
| ECS | 2 vCPU / 4 GiB / 40 GiB 起步 |
| 地域 | 香港或业务人员访问稳定的地域 |
| 操作系统 | Ubuntu 或 Alibaba Cloud Linux，按宝塔支持情况选择 |
| 面板 | 宝塔 Linux 面板 |
| 运行组件 | Node.js 20、PostgreSQL、Nginx、PM2 |
| 备份 | 每日 `pg_dump`，至少保留 7 天 |

## 3. 安全边界

本项目不是大型公网系统，但上线前仍保留最低安全底线：

1. 登录页不展示测试账号和默认密码。
2. 初始账号上线前必须更换强密码。
3. 正式环境默认关闭网页端数据重置入口。
4. 安全组不开放 `3000` 和 `5432`。
5. 数据库每天备份，且至少做一次恢复演练。
6. 生产 `.env` 不提交 Git。

## 5. 后续升级方向

如果未来访问人数增加或数据规模变大，可以再升级为：

1. ECS + 阿里云 RDS PostgreSQL。
2. 独立对象存储保存导出文件或附件。
3. 更完整的备份、监控、告警和审计报表。
4. PDA 到货后的扫码业务闭环。
