## 2. 项目背景

当前需要建设一套用于两级仓库货物管理的软件，帮助总仓、分仓的仓库人员和管理人员完成货物资料维护、厂家到货入库、终端店铺退换货入库、挪仓、销售出库、销售退回、库存查询和库存流转追踪等工作。

系统目标是减少人工记录错误，提高总仓、分仓和销售人员名下货物数据的实时性。每件货物通过唯一不可重复的条形码编号进行追踪，让货物从入库、挪仓、销售人员分配到未销售完退回的全过程可查询、可复核。系统第一阶段优先支持电脑网页端和 PDA 使用。

## 3. 建设目标

1. 建立统一的货物资料、总仓、分仓、库区、库位和销售人员基础数据。
2. 支持厂家到货入库、终端店铺退换货入库、挪仓、销售出库、销售退回和库存查询等核心仓储业务。
3. 支持按单件货物记录唯一条形码编号，用于后续查询和追踪。
4. 实时记录每件货物的库存位置、当前归属、条码状态和操作记录。
5. 支持查询货物库存现状、销售人员名下货物、生产日期/保质期信息和单件货物流转明细。
6. 支持多角色权限管理，保证不同岗位只能访问和操作授权范围内的数据。

## 4. 使用角色

| 角色 | 主要职责 | 典型操作 |
| --- | --- | --- |

| 仓库主管 | 管理仓库业务和处理异常 | 查看库存、查看库存流转、处理异常 |

| 采购/业务人员 | 查看与业务相关的库存和单据 | 查询库存、提交出入库单 |
| 财务/统计人员 | 查看库存价值和统计数据 | 查看报表、导出数据 |

## 5. 系统范围

### 5.1 MVP 范围

第一阶段优先完成以下能力：

1. 用户登录与角色权限。
2. 货物资料管理。
3. 两级仓库管理，支持总仓和分仓。
4. 入库管理。
5. 出库管理，支持挪仓和销售出库。
6. 库存查询，支持按仓库、销售人员、货物、单件条码查询。
7. 库存流转查询，支持查看单件货物的入库、挪仓、销售出库、销售退回变化明细。
8. 销售退回，支持未销售完货物从销售人员名下退回仓库。
9. 终端店铺退换货入库时登记生产日期，并按货物大类默认计算保质期。
10. PDA 端基础操作，支持扫码录入、入库、出库和库存查询。
11. 操作日志。

### 5.2 暂不纳入第一阶段的能力

以下能力可作为后续版本规划：

1. 出入库审核流程。
2. 临期和过期预警。
3. 库存盘点。
4. 库存预警。
5. 高级报表和财务成本核算。
6. 与 ERP、财务系统、电商平台或物流系统集成。
7. RFID 自动识别。
8. 自动补货算法。
9. 三级及以上仓库层级。
10. 移动端原生 App。
11. 终端店铺销售分配。

| CR-002 | 使用端 | 支持电脑网页端和 PDA |
| CR-003 | 条码规则 | 条形码编号按每件货物唯一编码，不可重复 |
| CR-004 | 审核流程 | 第一阶段出入库无需审核，提交后直接生效 |

| CR-007 | 出库类型 | 出库分为挪仓和销售出库两种 |
| CR-008 | 挪仓规则 | 挪仓指货物从总仓转移到分仓 |
| CR-009 | 销售出库规则 | 销售出库只需将货物分配到所属销售人员名下，无需分配到具体终端店铺 |
| CR-010 | 入库来源 | 入库来源分为厂家到货和终端店铺退换货 |

| CR-012 | 保质期规则 | 保健酒默认保质期为生产日期三年后；白酒默认无保质期 |
| CR-013 | 条码生成 | 条码生成方式无需系统关注，只需保证录入时不可重复 |
| CR-014 | 挪仓确认 | 挪仓不需要分仓确认，总仓提交后直接进入目标分仓库存 |
| CR-015 | 销售出库来源 | 总仓和分仓都可以销售出库 |
| CR-016 | 销售退回 | 与终端店铺退换货不同，仅将销售人员名下商品条码重新回流到仓库 |
| CR-017 | 销售退回字段 | 销售退回不登记终端店铺、生产日期和保质期，不重新计算保质期 |

## 7. 核心业务流程

### 7.1 入库流程

1. 操作员创建入库单。
2. 选择入库来源：厂家到货或终端店铺退换货。
3. 选择入库仓库，可选择总仓或分仓。
4. 选择或录入货物、数量、单件货物条形码编号、库位等信息。
5. 如一次入库多件货物，需录入或扫描每件货物的唯一条形码编号。
6. 如入库来源为终端店铺退换货，必须登记每件货物的生产日期。
7. 系统根据货物大类自动计算默认保质期：保健酒为生产日期三年后，白酒为无保质期。
8. 系统校验货物资料、仓库/库位状态、条形码编号唯一性、生产日期和数量格式。
9. 入库单提交后，对应条码货物进入所选仓库库存。
10. 系统生成库存流水和操作日志。

### 7.2 终端店铺退换货入库流程

1. 操作员创建入库单，并选择入库来源为终端店铺退换货。
2. 选择退换货进入的仓库，可选择总仓或分仓。
3. 录入或扫描退回货物的单件条形码编号。
4. 选择货物品类，系统识别货物大类为保健酒或白酒。
5. 登记该货物的生产日期。
6. 若货物大类为保健酒，系统默认保质期截止日期为生产日期三年后。
7. 若货物大类为白酒，系统默认保质期为空。
8. 提交后，货物进入所选仓库库存，并记录退换货入库流水。

### 7.3 出库流程

1. 操作员或业务人员创建出库单。
2. 选择出库类型：挪仓或销售出库。
3. 录入或扫描需要出库的单件货物条形码编号。
4. 系统校验条码对应货物是否在可出库库存中。
5. 出库单提交后，系统根据出库类型更新货物归属。
6. 系统生成库存流水和操作日志。

### 7.4 挪仓流程

1. 操作员创建挪仓出库单。
2. 选择源仓库，源仓库为总仓。
3. 选择目标分仓。
4. 扫描或录入需要挪仓的单件货物条形码编号。
5. 系统校验货物当前是否在总仓库存中，且条码未被冻结或作废。
6. 提交后，货物从总仓库存转入目标分仓库存。
7. 系统记录挪仓流水，包含源仓库、目标分仓、单件条码、操作人和操作时间。

### 7.5 销售出库流程

1. 操作员创建销售出库单。
2. 选择出库仓库，可选择总仓或分仓。
3. 选择所属销售人员。
4. 扫描或录入需要分配的单件货物条形码编号。
5. 系统校验货物当前是否在所选仓库库存中，且条码未被冻结或作废。
6. 提交后，货物从仓库库存转为销售人员名下货物。
7. 系统记录销售出库流水，包含出库仓库、销售人员、单件条码、操作人和操作时间。

### 7.6 销售退回流程

1. 操作员创建销售退回单。
2. 选择条码回流仓库，可选择总仓或分仓。
3. 扫描或录入未销售完货物的单件条形码编号。
4. 系统根据条码自动识别当前所属销售人员。
5. 系统校验货物当前是否归属于销售人员名下，且条码未被冻结或作废。
6. 提交后，货物条码从销售人员名下重新回流到所选仓库库存。
7. 系统记录销售退回流水，包含原所属销售人员、回流仓库、单件条码、操作人和操作时间。
8. 销售退回不登记终端店铺、生产日期和保质期，也不重新计算保质期。

### 7.7 PDA 操作流程

1. 操作员使用 PDA 登录系统。
2. 选择入库、出库、销售退回或库存查询功能。
3. 扫描单件货物条形码编号。
4. 系统带出货物信息、当前位置和当前归属。
5. 操作员确认数量或条码清单并提交。
6. 系统同步更新库存，并记录操作日志。

### 7.8 库存查询流程

1. 用户进入库存查询页面。
2. 按仓库、销售人员、货物、单件条形码编号、库位等条件查询。
3. 系统展示当前库存数量、所在仓库/库位、销售人员名下数量、单件条码信息、生产日期和保质期信息。
4. 用户可进入库存详情，查看某件货物或某个条码的库存流转记录。
5. 库存流转记录展示入库、挪仓、销售出库、销售退回、调整来源、发生时间、操作人和变动前后归属。

### 7.9 盘点流程

1. 仓库主管创建盘点任务。
2. 系统生成盘点清单。
3. 操作员录入实际盘点数量。
4. 系统计算账面数量与实际数量差异。
5. 仓库主管确认盘盈/盘亏处理。
6. 系统调整库存并记录盘点流水。

> 盘点不是第一阶段必须功能，可在后续版本实现。

## 10. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 易用性 | 常用操作步骤尽量少，支持模糊搜索、扫码录入和 PDA 快速操作 |
| 性能 | 常用库存查询应在 3 秒内返回结果 |
| 安全性 | 密码加密存储，关键接口需要权限校验；删除、清空、重置等高危操作仅允许超级管理员执行 |
| 可追溯性 | 所有影响库存的操作必须有单据和流水 |

| 兼容性 | 电脑端建议优先支持 Chrome、Edge 等现代浏览器；PDA 端需适配常见安卓浏览器或 PDA 内置浏览器 |
| 数据备份 | 需要提供数据库备份和恢复方案 |

## 11. 业务规则

1. 货物编码在系统内必须唯一，用于标识货物品类。
2. 仓库编码在系统内必须唯一。
3. 仓库只分两级：总仓和分仓。
4. 库位编码在同一仓库内必须唯一。
5. 分仓必须归属到一个总仓。
6. 单件条形码编号在系统内必须唯一，不允许重复入库。
7. 系统不负责条形码生成方式，只负责录入后的唯一性校验和库存追踪。
8. 入库来源只分为厂家到货和终端店铺退换货。
9. 终端店铺退换货入库必须登记生产日期。
10. 货物大类为保健酒时，默认保质期截止日期为生产日期三年后。
11. 货物大类为白酒时，默认无保质期。
12. 已完成的单据不可随意修改，只能通过作废或调整流程处理。
13. 所有入库、挪仓、销售出库、销售退回、盘点调整都必须生成库存流水。
14. 出库时，扫描的单件条码必须处于可出库状态，否则系统必须阻止提交。
15. 停用的货物、仓库、库位、销售人员不可被新增业务单据引用。
16. 第一阶段出入库无需审核，提交后直接影响库存或货物归属。
17. 挪仓只能从总仓转移到分仓，且不需要分仓确认。
18. 销售出库可从总仓或分仓发出。
19. 销售出库只分配到销售人员名下，不要求分配到终端店铺。
20. 终端店铺退换货和销售退回是两个不同业务。
21. 终端店铺退换货属于入库来源，需要登记生产日期，并按货物大类处理保质期。
22. 销售退回仅处理销售人员名下未销售完货物的条码回流至仓库，不登记终端店铺、生产日期和保质期。
23. 销售退回不改变该条码原有生产日期和保质期信息。
24. 库存查询和库存流转必须能定位到具体单件条形码编号。
