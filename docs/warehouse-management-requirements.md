# 箱码流向追踪系统需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 当前版本 | 流向追踪版 Web v1.6.0（待发布） |
| 更新日期 | 2026-08-12 |
| 文档状态 | 已确认并实施 |
| 适用范围 | 电脑网页端、Android PDA、共享 API、PostgreSQL 数据库、勤策签收连接器 |

## 2. 产品目标

本系统只负责回答两个核心问题：某个唯一箱码从哪里出库、现在在哪里；勤策是否已反馈该箱货物的商品和签收店铺。

1. 每箱货物使用一个唯一且不可重复的条码。
2. 仓库人员出库时只扫描箱码并登记去向，不选择商品、不维护本系统数量库存。
3. 商品名称、商品单位、签收店铺和签收时间以勤策扫码明细为准。
4. 未售货物和店铺退货使用同一个扫码回库窗口。
5. 正常业务的出库、回库、仓库流转和勤策签收事件形成不可由日常操作删除的条码履历；超级管理员仅可按管理纠错规则清理已确认的错误本地条码记录。
6. 旧商品、数量库存和历史业务表继续保留用于兼容与审计，但不再参与新的日常流程。

## 3. 角色与权限

| 角色 | 权限 |
| --- | --- |
| 超级管理员 | 全部流向业务、出库复核与修订、单据纠错与回滚删除、错误条码记录删除、基础资料、账号、日志、勤策同步、系统维护和重置 |
| 仓库管理员 | 快速出库、扫码回库、首次出库复核、条码查询、流转单据查询和基础资料维护 |
| 只读查询人员 | 首页、条码查询、流转单据和勤策签收查询 |

前端入口与后端 API 必须执行相同权限规则。未登录返回 401，无权限返回 403，业务校验失败返回 400 或 409。

## 4. 核心数据模型

### 4.1 条码档案

每个条码保存以下当前信息：

1. 唯一箱码。
2. 当前归属类型：仓库、销售人员或终端店铺。
3. 当前仓库、销售人员或勤策返回的终端店铺名称。
4. 签收状态：待签收、已签收或签收异常。
5. 勤策返回的商品名称、商品单位和签收时间。
6. 最近变动时间及档案状态。

当前归属和签收状态是两个独立维度。例如，扫码回库后的箱码当前归属为仓库，但仍可保留此前勤策签收事实。

### 4.2 流转单据与履历

1. 快速出库、仓库流转和扫码回库均生成流转单据。
2. 每个箱码写入一条对应履历，记录来源、去向、操作人、时间和单号。
3. 勤策签收事件写入独立履历，原销售人员出库或目标仓库挪仓记录永久保留。
4. 相同业务请求编号重复提交时不得重复生成单据或履历。
5. 单次作业最多提交 500 个箱码。
6. 多张分批出库单可合并为一张新的出库单：销售出库要求来源仓库和销售人员相同，挪仓要求来源仓库和目标仓库相同；两类业务不得混合合并。
7. 合并完成后，列表、详情、查询、复核和纠错均只显示新出库单；原分批单不再显示、不能单独打开，也不提供拆分恢复功能。
8. 合并不得重复创建或删除条码流转。系统在后台保留原分批单关联和已有复核版本用于审计，但条码履历统一显示新出库单号。
9. 新出库单的业务时间、排序时间和日期筛选时间均取所选分批单中最晚的业务时间，不使用合并操作时间。
10. 单次可合并 2 至 20 张出库单且最多 5000 个箱码；允许跨日期合并，但必须二次确认。
11. 待复核和已复核单据可以混合合并；新出库单统一进入待复核，合并前已有复核版本仅在后台审计中保留。

### 4.3 出库复核与纠错审计

1. 销售出库和挪仓提交后立即生效，同时进入待复核；复核是数量记录，不是审批，不阻断条码流转。
2. 实际总出货数量必填并允许为 0；商品品类数量选填。实际总数、有效扫码数与品类合计不一致时只提示，不阻止保存。
3. 仓库管理员和超级管理员可完成首次复核，只有超级管理员可修订；每次保存产生不可覆盖的历史版本。
4. 路线纠正永久记录原始内容、纠正前后值、操作者、时间和备注。复核后的纠错或条码删除必须显式标记。
5. 已有后续勤策签收、扫码回库或再次出库的条码，不允许直接纠正或回滚删除原出库业务。

### 4.4 勤策签收记录

1. 签收记录以条码、扫码时间、扫码人和收货单位等信息组成唯一事件。
2. 重复导入同一事件只计一次，不依赖 Excel 文件名或是否保存原文件。
3. 签收事件按勤策扫码时间排序，不能用导入时间覆盖后来发生的回库或其他流转。
4. 同一箱码可先在店铺 A 签收，之后直接在店铺 B 再次签收；当前归属改为店铺 B，两个事件均保留。

## 5. 基础资料

本系统日常维护：

1. 仓库：编码、名称、负责人、启停状态。
2. 销售人员：编码、姓名、电话、区域、启停状态。
3. 商品品类：仅包含名称和启停状态。成功匹配的勤策记录自动补建新名称，也可由仓库管理员或超级管理员手工新增、停用和恢复。
4. 用户及角色。

商品品类名称去除首尾空格并合并连续空格后严格匹配，不提供模糊匹配、别名和重命名。停用品类再次出现在勤策中不会自动恢复。品类目录不等同于旧库存商品，不参与快速出库或数量库存。终端店铺不在本系统维护，其名称由勤策签收结果回填。旧商品和终端店铺数据不得因本次升级被物理删除。

## 6. 核心业务流程

### 6.1 快速出库到销售人员

流程：选择来源仓库 → 选择销售人员 → 连续扫描混合商品箱码 → 提交。

1. 不选择商品，不校验本系统商品库存。
2. 新条码在提交时建立追踪档案。
3. 已有条码必须当前归属于所选来源仓库。
4. 提交后当前归属为销售人员，签收状态为待签收。
5. 商品名称显示“等待勤策签收回填”，直到取得有效签收记录。

### 6.2 快速出库到仓库

流程：选择来源仓库 → 选择不同的目标仓库 → 连续扫描箱码 → 提交。

1. 来源和目标仓库必须不同。
2. 提交后当前归属立即变为目标仓库，无需接收确认。
3. 已有条码必须当前归属于所选来源仓库。
4. 不改变旧数量库存账。
5. 目标仓库可不再补录销售出库而直接配送；之后取得的有效勤策签收会把当前归属从目标仓库更新为终端店铺。
6. 每次挪仓开启一个新的待签收周期，挪仓单据可查看本周期的整单和分商品签收率。

### 6.3 出库复核

1. 网页端“出库复核”统一列出待复核或已复核的出库单；扫码回库无需复核，PDA 不提供复核入口。
2. 分批单合并后只复核新生成的出库单，原分批单不再作为独立业务单据出现。
3. 复核人必填实际总出货数量，可选填各商品品类数量。数量差异醒目提示但允许提交。
4. 复核完成后的修订只允许超级管理员执行，旧版本及当时的有效扫码数永久保留。
5. 已复核单据的整单签收率以最新复核版本的实际总出货数量为分母；待复核和历史免复核单据仍以本次流转周期的有效箱码数为分母。分母为 0 时不计算比例。
6. 已复核单据的各商品签收率以最新复核版本中对应商品品类数量为分母。已填写但尚无签收的品类显示 0%；勤策识别出复核中未填写数量的商品时保留真实签收与异常数量，但比例显示待补充。
7. 品类合计少于实际总数时显示未分配品类数量；签收或异常数量超过复核数量时保留真实比例和超量告警，不自动修改复核数据。

### 6.4 扫码回库

流程：选择回库仓库 → 连续扫描混合箱码 → 提交。

1. 销售人员未售货物、终端店铺退货和系统尚未建档的外部回流可混合提交。
2. 不选择商品、销售人员或来源店铺，不填写生产日期和数量。
3. 系统按条码当前归属自动生成来源信息。
4. 未建档条码创建外部流入档案，商品等待勤策补充。
5. 已在任一仓库的条码拒绝重复回库；跨仓移动应使用快速出库到仓库。
6. 回库不改变旧数量库存账。

### 6.5 勤策终端签收同步

流程：浏览器连接器取得指定日期范围签收数据 → 上传至本系统 → 去重 → 关联箱码 → 按事件时间重算归属。

1. 有效签收可对应此前的销售出库或挪仓，并回填商品名称、单位、收货店铺和签收时间。
2. 当前归属变为勤策返回的终端店铺，状态变为已签收。
3. 原销售人员继续保留在出库履历中。
4. 商品名称首次确认后不得被冲突名称静默覆盖；冲突时标记签收异常并保留原始记录。
5. 无法关联，或签收前不存在销售出库、挪仓或连续勤策签收的记录，保留待核对，不自动篡改当前归属。
6. 自动任务默认每周一同步上一自然周；手动同步补跑到当前时间。系统内部去重保证重叠日期不会重复记账。
7. 只有成功关联为 MATCHED 的记录才能自动创建商品品类并关联条码；未匹配和冲突记录不得污染品类目录。

### 6.6 管理纠错与回滚删除

1. 超级管理员可物理删除已确认的错误条码档案、本地流转和单据关联；存在勤策签收记录或已经核销的条码禁止删除。
2. 删除后相同条码可作为新条码再次扫码建档；删除唯一条码后形成的空单一并清理。勤策签收记录始终不在此删除范围内。
3. 超级管理员可纠正出库单的来源仓库、销售出库/挪仓类型及去向；本轮不提供回库单纠错。
4. 只有全部箱码均无后续流转时，出库单才可回滚删除。已有条码恢复到出库前归属；由该业务首次创建且没有勤策记录的条码档案删除；单据、复核和纠错业务记录物理删除。
5. 所有高风险操作均要求二次确认并写入中文操作日志；原因或备注选填。

## 7. 查询与界面

### 7.1 首页

首页显示总追踪箱码、待签收、已签收、签收异常、当前归属分布、最近流转和勤策同步状态。首页只读取摘要和有限条数，不加载全量箱码。

### 7.2 条码查询

1. 支持完整箱码精确查询。
2. 支持按签收状态和当前归属类型筛选。
3. 支持按勤策商品名称或签收店铺名称搜索。
4. 列表使用服务端分页。
5. 详情显示当前归属、签收状态、勤策商品、所有流转履历和勤策签收记录。

### 7.3 流转单据

支持按销售出库、仓库流转、扫码回库和业务日期范围筛选，显示单号、来源、去向、生命周期、复核状态、有效与撤销箱码数、条码预览、操作人和时间。销售出库单和仓库流转单详情显示本次流转周期的整单签收率、各项商品签收率、当前统计口径、复核版本、纠错历史及每个箱码状态；待复核和历史免复核单据使用有效追踪箱码口径，已复核单据使用最新复核数量口径。销售出库和挪仓均支持将同一路线的分批单据合并成一张新的出库单；合并后列表和详情只显示新单，不再展示原分批单。

### 7.4 勤策签收

显示连接器任务、同步批次、导入范围、记录数量、匹配结果、重复结果和异常信息。失败信息不得出现在页面顶部，应在当前面板、弹窗或底部提示中展示。

## 8. 安全、可靠性与性能

1. 密码使用 scrypt 保存；旧明文密码首次成功登录后自动升级。
2. 登录失败使用轻量限流。
3. 数据库不可用时显示故障状态，不回退到演示数据或浏览器本地库存。
4. 快速出库和扫码回库支持客户端请求编号；网络结果不明时复用原编号重试。
5. 同一编号对应不同业务内容时返回 409。
6. 条码和流转查询必须服务端分页，精确条码优先使用唯一索引。
7. 500 条扫码提交在本地测试环境目标控制在 5 秒内。
8. 系统提供不泄露数据库地址和密钥的健康检查。
9. 正式数据库备份经结构校验后上传私有 OSS；本机和 OSS 按既定保留周期清理。
10. 条码删除、单据删除、单据纠正、复核及复核修订均记录操作人、时间、前后数据和系统结果，不允许覆盖操作日志和仍然存在的审计记录。

## 9. 系统维护与兼容

1. 高危重置只允许超级管理员执行，并要求精确确认文字 `确定重置`。
2. 重置清除业务、追踪、同步和基础资料数据，保留用户与角色，不写回测试数据。
3. 旧商品、库存、入库单、出库单和退回单模型暂时保留，不再在新主界面暴露。
4. 本次升级不主动清空旧数据，不把旧数量库存自动转换为新的权威库存。
5. 操作日志中的动作和说明以中文显示。

## 10. 暂不纳入

本系统不承担权威商品主数据、仓库数量库存、厂家到货、生产日期、保质期、盘点、安全库存、财务成本、终端店铺主数据和人工店铺分配。简化商品品类目录仅用于复核数量记录，权威商品名称和单位仍以勤策为准。
