# 仓库货物管理软件需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 当前版本 | Web 1.0 |
| 更新日期 | 2026-07-10 |
| 文档状态 | 已确认并实施 |
| 适用范围 | 电脑网页端、共享 API、PostgreSQL 数据库 |

## 2. 产品目标

系统服务于约 10 人的小团队，用于管理多个平级仓库、销售人员名下货物和已进入扫码流程的单件条码。

1. 仓库库存回答“每个仓库每种货物还剩多少件”。
2. 条码追踪回答“已经扫过的某件货物现在在哪里、经过哪些流转”。
3. 厂家到货以数量登记为主，避免无必要的逐件扫码。
4. 出库、退回和异常维护保持可追溯、可复核、不可超卖。
5. 在 100,000 条以上条码数据下仍能分页查询和精确检索。

## 3. 角色与权限

| 角色 | 权限 |
| --- | --- |
| 超级管理员 | 全部业务、基础资料、用户、日志、单据撤销、条码维护、库存修正和系统重置 |
| 仓库管理员 | 到货入库、扫码出库、退回入库、基础资料维护、库存和单据查询 |
| 只读查询人员 | 首页、库存查询、条码流转和单据查询 |

前端入口和后端 API 必须执行相同权限规则。未登录返回 401，无权限返回 403，业务校验失败返回 400。

## 4. 核心数据模型

### 4.1 仓库数量账

每个 `仓库 + 货物` 组合保存一个当前数量。任何入库、出库、退回、挪仓、核销、撤销或人工修正都必须原子更新数量，并写入不可变的数量流水。

约束：

1. 库存数量不得小于 0。
2. 多设备并发出库时只允许库存充足的事务成功。
3. 仓库均为平级，不存在总仓、分仓或父子仓库字段。
4. 每个仓库自动维护一个内部默认库位，用户无需区分库位。

### 4.2 条码追踪账

1. 每件进入扫码流程的货物使用唯一且不可重复的单件条码。
2. 厂家到货不创建条码记录。
3. 首次扫码出库时，系统可根据所选货物创建条码追踪档案。
4. 条码当前归属为仓库或销售人员，并保存完整流转。
5. 条码更正不改变货物身份或库存；旧条码仍能查到当前条码和历史。
6. 核销保留条码和历史，不允许把已使用条码重新分配给另一件货物。

## 5. 基础资料

系统维护以下资料：

1. 货物：编码、名称、大类、单位、规格、状态和排序权重。
2. 仓库：编码、名称、负责人、状态和排序权重。
3. 销售人员：编码、姓名、电话、区域和状态。
4. 终端店铺：名称、联系人、电话、地址和状态。
5. 用户及角色。

新增或编辑使用弹窗。超级管理员可直接删除未被库存、单据或其他业务引用的基础资料；被引用资料必须停用或先处理关联业务。

## 6. 核心业务流程

### 6.1 厂家到货入库

流程：选择仓库 → 添加货物明细 → 填写每种货物数量 → 提交。

结果：

1. 仓库商品库存增加。
2. 生成厂家到货入库单和数量流水。
3. 不登记生产日期。
4. 不创建单件条码。

### 6.2 扫码出库

流程：选择来源仓库 → 选择货物 → 选择去向类型 → 选择销售人员或目标仓库 → 扫码 → 提交。

共同规则：

1. 单次最多 500 个条码。
2. 扫码数量不得超过来源仓库该货物库存。
3. 条码清单逐条显示校验状态。
4. 条码已绑定其他货物、处于异常状态或不在所选来源仓库时拒绝提交。

去向为销售人员：

1. 来源仓库库存减少。
2. 首次条码创建追踪档案。
3. 条码归属变为销售人员。

去向为仓库：

1. 来源仓库库存减少，目标仓库库存增加。
2. 来源仓库和目标仓库必须不同。
3. 条码归属变为目标仓库。
4. 不需要接收方确认。

### 6.3 销售退回

流程：选择退回仓库 → 扫描条码 → 提交。

1. 不手动选择销售人员，系统按条码当前归属识别。
2. 条码必须当前在销售人员名下。
3. 退回仓库库存增加，条码归属变为仓库。
4. 不登记终端店铺、生产日期或保质期。

### 6.4 终端店铺退换货

流程：选择退回仓库 → 选择终端店铺 → 选择货物 → 填写数量和生产日期 → 扫码 → 提交。

1. 数量必须等于条码数量，单次最多 500 件。
2. 新条码允许创建追踪档案。
3. 销售人员名下已有条码自动回流仓库。
4. 已在仓库的条码拒绝重复入库。
5. 保健酒默认保质期为生产日期三年后，白酒无默认保质期。
6. 条码已有生产日期时不覆盖原档案；本次生产日期仍保存在单据明细。

## 7. 查询与导出

### 7.1 首页

首页只展示摘要：

1. 各仓库货物储备最多 10 条，按仓库和货物排序权重决定。
2. 销售人员持有最多显示 6 条高度，区域内滚动。
3. 最近条码流转最多 8 条。
4. 首页不得加载全量条码或全量单据。

### 7.2 库存查询

1. 仓库商品库存按数量展示。
2. 可追踪条码按归属、仓库、销售人员、货物和关键字服务端分页。
3. 完整当前条码或历史条码可精确查询。
4. 条码详情用弹窗展示当前归属、生产日期、保质期、更正记录和完整流转。
5. 详情上部信息固定，仅流转记录区域滚动。

### 7.3 单据查询

1. 支持业务类型、状态、完整条码、页码和单页数量筛选。
2. 查询覆盖全库，不只读取最近单据。
3. 列表只返回少量条码预览，详情和导出按需加载完整明细。
4. 可勾选最多 50 张单据导出，CSV 每行显示一个条码；无条码数量入库显示一行数量明细。

## 8. 单据撤销

1. 单据不物理删除，撤销后保留并标记为已作废。
2. 撤销必须填写原因，并记录原单号、原业务、原操作人、撤销人和撤销时间。
3. 厂家到货撤销扣回原数量；库存不足时拒绝。
4. 出库撤销恢复来源仓库数量和条码提交前归属。
5. 退回类单据按提交前归属快照恢复。
6. 任一条码在原单据后已有新流转时，整张单据拒绝撤销并指出冲突条码。
7. 旧版本或压测单据缺少快照时标记为不支持撤销。

## 9. 超级管理员异常维护

1. **更正条码**：填写新条码和原因，保留旧条码映射和更正流水。
2. **货物核销**：填写原因；仓库在库货物库存减 1，销售人员名下货物不改变仓库数量。
3. **彻底删除错误档案**：只允许删除无单据、无流水、无更正引用的空白档案。
4. **人工库存修正**：选择仓库和货物，填写非零增减数量及原因，写入人工修正流水。
5. **系统重置**：输入精确确认文字 `确定重置`，清除业务和基础资料，保留用户及角色，不写回演示数据。

## 10. 安全与性能

1. 密码使用 scrypt 保存；旧明文密码首次成功登录后自动升级。
2. 登录失败使用轻量限流。
3. 数据库不可用时显示故障状态，不展示演示库存或本地缓存。
4. 500 条扫码提交本地目标低于 5 秒。
5. 完整条码查询本地目标低于 500 ms。
6. 100,000 条条码下首页、库存第一页和单据第一页应保持可用。
7. 入库、出库和销售退回写接口支持客户端请求编号；相同编号和相同业务内容重复提交时只能产生一次库存变动。
8. 相同请求编号对应不同业务内容时必须拒绝，现有未传请求编号的 PDA 请求保持兼容。
7. 列表接口必须限制单页数量，禁止无边界读取。

## 11. 暂不纳入

审批、盘点任务、临期预警、安全库存预警、财务成本、ERP/电商/物流集成、RFID、自动补货和终端店铺级销售分配暂不属于 Web 1.0。
