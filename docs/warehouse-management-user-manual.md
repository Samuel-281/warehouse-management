# 仓库货物管理软件使用说明书

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 当前版本 | Web 1.0 |
| 更新日期 | 2026-07-14 |
| 适用对象 | 超级管理员、仓库管理员、只读查询人员 |
| 数据模型 | 数量库存 + 条码追踪双账本 |

## 2. 重要概念

| 名称 | 说明 |
| --- | --- |
| 仓库库存 | 每个仓库每种货物的当前数量，与条码数量分开计算 |
| 可追踪条码 | 已经过扫码业务、可查看当前归属和流转历史的单件货物 |
| 厂家到货 | 按仓库、货物和数量入库，不扫码 |
| 扫码出库 | 从仓库扣减数量，并把扫码货物分配给销售人员或另一个仓库 |
| 待签收 | 已销售出库、暂未取得勤策签收结果的条码 |
| 已签收 | 勤策已返回收货单位，当前归属为该终端店铺的条码 |
| 统一退回入库 | 待签收、已签收和未建档外部退货在同一窗口按条码回流仓库 |
| 撤销单据 | 保留原单据并反向恢复库存影响，不等于删除记录 |
| 核销 | 货物不再作为正常库存，但条码和历史永久保留 |

所有仓库平级，不区分总仓和分仓。页面中的默认库位由系统内部自动维护，日常操作无需区分库位。

## 3. 登录和权限

1. 打开网站，输入管理员分配的账号和密码。
2. 超级管理员可看到全部入口。
3. 仓库管理员可操作入库、出库、退回和基础资料，但看不到系统维护。
4. 只读查询人员只可进入首页、库存查询和单据查询。
5. 登录连续失败时稍后重试；如忘记密码，请联系超级管理员。

## 4. 首页

首页用于快速查看：

1. 仓库当前库存总量。
2. 系统可追踪条码数。
3. 待签收和已签收条码数。
4. 各仓库货物储备，最多 10 条，按基础资料排序权重排列。
5. 待签收货物按销售人员统计，区域最多显示 6 条高度并可滚动。
6. 最近 8 条条码流转。

点击右上角刷新图标可重新读取数据库。若数据库不可用，页面会显示“暂时无法读取业务数据”，不会显示模拟数据。

## 5. 基础资料

### 5.1 新增和编辑

1. 进入“基础资料”。
2. 选择新增货物、仓库或销售人员。
3. 在弹窗内填写必填字段并保存。
4. 新增仓库后，系统自动创建默认库位。
5. 点击资料行的“编辑”或“启用/停用”进行维护。

错误信息显示在当前弹窗底部，不会跳到页面顶部。

### 5.2 首页排序

货物和仓库资料表左侧带有拖拽手柄。上下拖动可调整首页“各仓库货物储备”的展示优先级。

### 5.3 删除

只有超级管理员可直接删除基础资料。点击删除后在确认弹窗中确认；已被库存或单据引用的资料会被系统拒绝删除，通常应改为停用。

## 6. 到货入库

厂家到货不扫码。

1. 进入“到货入库”。
2. 选择入库仓库。
3. 选择货物并填写到货数量。
4. 检查提交区中的仓库、货物和数量。
5. 点击“提交入库”。

提交后仓库数量增加，生成入库单和数量流水；可追踪条码列表不会增加。

## 7. 扫码出库

### 7.1 分配给销售人员

1. 进入“扫码出库”。
2. 选择来源仓库和货物。
3. 去向选择“销售人员”，再选择具体人员。
4. 连续扫描或粘贴条码，按回车或点击加入。
5. 查看每个条码的校验状态；红色条码必须先移除或修正。
6. 点击提交。

提交后来源仓库数量按条码数减少，条码进入“待签收”，并保留所选销售人员作为待签收归属。首次出现的条码会在此时建立追踪档案。

### 7.2 发往另一个仓库

1. 去向选择“仓库”。
2. 选择与来源仓库不同的目标仓库。
3. 扫码并检查条码清单。
4. 提交后来源仓库减少、目标仓库增加，条码归属变为目标仓库。

单次最多处理 500 个条码。出库数量超过来源库存时系统拒绝提交。

## 8. 退回入库

1. 进入“入库”，选择“退回入库”。
2. 选择回流仓库。
3. 选择“未建档条码默认货物”；该选择只用于系统从未见过的外部退货条码。
4. 连续扫描退回条码。待签收货物、勤策已签收货物和未建档外部退货可混合录入。
5. 检查每条条码的校验状态并提交。

系统会自动识别已知条码原归属，无需人工选择销售人员或终端店铺，也不登记生产日期。成功后每个条码使仓库库存增加 1 并回到所选仓库；已经在仓库的条码会标红并禁止重复入库。

## 9. 勤策终端签收

1. 在“查询”中进入“终端签收”，可查看同步状态、导入记录和签收明细。
2. 有效签收会把条码从“待签收”更新为“已签收”，当前归属显示勤策的“收货单位名称”。
3. 签收同步不增加或减少仓库库存，原销售人员仍保留在销售出库履历中。
4. 同一条码后来在另一家店铺再次签收时，当前终端归属会按勤策扫码时间更新，历史店铺仍可在签收履历中查看。
5. 迟到导入的旧签收只补充履历，不会覆盖后来已经发生的退回入库。
6. 无法关联或流转顺序冲突的记录显示为“签收异常”，需要人工核对，不会自动改库存。

## 10. 库存查询

### 10.1 筛选

1. 归属类型选择全部、仓库、待签收或终端店铺。
2. 选择待签收时可继续按销售人员筛选；已签收条码显示勤策终端店铺名称。
3. 可继续按货物筛选。
4. 关键字支持货物名称、编码或条码；输入完整当前条码或历史条码可精确查询。
5. 每页可显示 20、50 或 100 条。

页面上方“仓库商品库存”显示数量账；下方“可追踪条码列表”显示已扫码货物，两者含义不同。

### 10.2 条码详情

点击条码行打开详情弹窗。上方显示货物、当前归属、生产日期、保质期和最近更正记录；下方流转区域可独立滚动并导出 CSV。

## 11. 单据查询和导出

1. 可按业务类型、正常/已作废状态和完整条码筛选。
2. 勾选需要导出的单据，点击“导出已选”。
3. 单次最多导出 50 张。
4. 扫码单据在 CSV 中每行显示一个条码；厂家数量入库按数量明细导出。
5. 列表只显示少量条码预览，完整明细仅在导出或详情读取。

## 12. 超级管理员维护

### 12.1 账号管理

所有用户可在左下角账号区域修改自己的密码，修改后其他设备的登录会话会失效。超级管理员可在账号列表编辑显示姓名、角色和启停状态，也可重置其他账号密码；系统不会允许停用当前超级管理员或移除最后一个启用的超级管理员。

### 12.2 撤销单据

1. 在单据查询勾选正常且支持撤销的单据。
2. 点击“撤销已选”。
3. 在弹窗填写至少 2 个字符的原因。
4. 确认后系统恢复库存和条码提交前归属，原单据保留并显示“已作废”。

如果任一条码在原单据后已有签收、退回、挪仓、核销或其他流转，整张单据不会撤销，提示中会指出冲突条码。

### 12.3 更正条码

在条码详情点击“更正条码”，填写未使用的新条码和原因。更正不改变货物和库存；旧条码仍可查询到当前条码及历史。

### 12.4 货物核销

在条码详情点击“货物核销”并填写原因。仓库在库货物会同步减少库存 1 件；待签收或已签收货物不改变仓库库存。核销后条码和历史仍保留。

### 12.5 删除错误档案

“删除错误档案”只适用于从未产生单据、流水或更正历史的空白误建档案。正常业务记录请使用撤销或核销。

### 12.6 人工库存修正

在库存查询的仓库数量表点击“修正库存”。增加填正数，减少填负数，并填写原因。系统不允许修正后库存为负数，成功后记录“人工库存修正”流水。

### 12.7 数据一致性检查

在系统维护点击“开始检查”。检查只读取数量账、条码归属、流水和作废单据，不会自动修复。显示“错误”的记录需要根据建议核对单据并使用撤销、更正、核销或库存修正处理；“缺少历史基线”只是旧数据迁移提示，不代表当前库存错误。

### 12.8 系统重置

在系统维护输入精确文字 `确定重置` 后执行。该操作清除业务数据和基础资料，保留用户与角色，不写入测试数据；完成后需要重新登录。

### 12.9 运行与备份状态

系统维护页显示应用、数据库、Web/API 版本和最近一次自动备份结果。备份失败或数据库连接失败时，应先停止业务提交并联系维护人员，不要反复执行入库或出库。

## 13. 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 条码在清单中正常但提交失败 | 另一设备可能先提交了同一条码；刷新校验后移除冲突条码 |
| 提示库存不足 | 核对来源仓库和货物，必要时由超级管理员查明差异后修正 |
| 旧条码查不到 | 使用完整旧条码精确查询；若仍无结果，确认是否从未进入扫码流程 |
| 无法撤销单据 | 查看提示中的冲突条码；存在后续流转时应先处理后续业务或使用核销 |
| 页面显示数据库故障 | 检查 PostgreSQL 和网站服务，恢复后点击重新连接 |
| 大量数据页面缓慢 | 使用具体归属、货物或完整条码缩小范围，不使用无边界导出 |
| 提交后网络中断、结果不确定 | 保持当前表单并再次点击提交；系统使用相同请求编号确认首次结果，不会重复记账 |
