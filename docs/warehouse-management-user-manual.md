# 箱码流向追踪系统使用说明书

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 当前版本 | 流向追踪版 Web v1.6.0（待发布） |
| 更新日期 | 2026-08-12 |
| 适用对象 | 超级管理员、仓库管理员、只读查询人员 |
| 核心用途 | 箱码流向 + 勤策签收追踪 |

## 2. 重要概念

| 名称 | 说明 |
| --- | --- |
| 箱码 | 每箱货物唯一且不可重复的条码 |
| 当前归属 | 箱码当前在仓库、销售人员或勤策签收店铺 |
| 待签收 | 已交给销售人员，尚未收到勤策有效签收结果 |
| 已签收 | 勤策已返回收货店铺和商品信息 |
| 签收异常 | 商品冲突、关联失败或流转顺序需要人工核对 |
| 快速出库 | 只记录来源仓库、去向和箱码，不选择商品、不扣本系统库存 |
| 扫码回库 | 未售货物与店铺退货统一扫回仓库 |
| 出库复核 | 出库已生效后的数量核对记录，不是审批，不会阻断箱码流转 |
| 合并出库 | 将同一路线的多张分批单合并成一张新的出库单 |

当前归属和签收状态并不是同一个字段。箱码回库后当前归属是仓库，但此前的已签收事件和销售人员出库记录仍会保留在履历中。

## 3. 登录和权限

1. 输入服务器地址、账号和密码登录。
2. 超级管理员可使用全部业务和维护功能。
3. 仓库管理员可进行快速出库、扫码回库、首次出库复核、查询和基础资料维护。
4. 超级管理员还可修订复核、纠正或回滚删除出库业务，以及彻底删除没有勤策签收记录的错误条码。
5. 只读人员只能查询。
6. 修改或重置密码后，其他设备上的旧会话会失效。

## 4. 首页

首页用于快速查看：

1. 系统已追踪箱码总数。
2. 待签收、已签收和签收异常数量。
3. 当前在仓库、销售人员和终端店铺的箱码分布。
4. 最近箱码流转。
5. 最近勤策同步状态。

首页不会加载全部箱码。需要查看具体货物时进入“条码查询”。

## 5. 基础资料

基础资料维护三个板块：

1. **仓库**：编码、名称、负责人和启停状态。
2. **销售人员**：编码、姓名、电话、区域和启停状态。
3. **商品品类**：仅维护名称和启停状态。勤策成功匹配到新商品名称时自动新增，也可手工新增、停用或恢复。

商品品类不参与库存和出库扫码，也不提供重命名。停用后再次收到同名勤策数据不会自动恢复。终端店铺不在本系统手工维护；商品名称、单位和签收店铺会在勤策签收后自动显示。旧资料仍保存在数据库中用于历史兼容。

## 6. 快速出库

### 6.1 出库给销售人员

1. 进入“快速出库”。
2. 选择来源仓库。
3. 去向选择“销售人员”，再选择具体人员。
4. 连续扫描箱码；不同商品可以混合扫描。
5. 等待所有条码完成校验。
6. 删除红色异常条码后点击“提交出库”。

提交后箱码当前归属为该销售人员，签收状态为“待签收”。商品名称暂时显示“待勤策补全”。

### 6.2 流转到另一个仓库

1. 去向选择“仓库”。
2. 选择与来源仓库不同的目标仓库。
3. 扫描箱码并提交。

提交后箱码立即归属于目标仓库，无需接收确认，并进入本次挪仓的待签收周期。目标仓库可以直接配送，无需先补做一次销售出库；勤策返回有效签收后，箱码当前归属会由目标仓库更新为签收店铺。该操作只记录条码流向，不改变旧数量库存。

### 6.3 校验说明

1. 新箱码显示“新条码”，提交后建立追踪档案。
2. 已有箱码必须当前在所选来源仓库。
3. 已核销、已结束追踪或归属不符的箱码不能提交。
4. 单次最多 500 个箱码。
5. 网络中断且结果不确定时保留当前清单再次提交，系统会使用相同请求编号确认，不会重复记录。

## 7. 扫码回库

1. 进入“扫码回库”。
2. 选择回库仓库。
3. 连续扫描未售货物、店铺退货或外部回流箱码，三类货物可以混合。
4. 等待所有条码校验完成。
5. 点击“提交回库”。

回库不需要选择商品、销售人员或来源店铺，也不填写生产日期。系统会按每个箱码的当前归属自动写入来源；未知箱码会创建“外部流入”追踪档案。已经在仓库的箱码不能重复回库。

店铺 A 的退货如果未回仓就直接销售给店铺 B，不需要补做回库。后续勤策签收店铺 B 后，当前归属会更新到店铺 B，店铺 A 和店铺 B 的签收都保留在履历中。

## 8. 条码查询

“条码查询”内包含三个标签页。

### 8.1 条码追踪

1. 输入完整箱码可精确查询。
2. 也可按勤策商品名称、签收店铺、签收状态和当前归属筛选。
3. 点击条码行查看详情。
4. 详情显示当前归属、签收状态、商品、单位、完整流转和所有勤策签收记录。

### 8.2 流转单据

可按销售出库、仓库流转、扫码回库和开始/结束日期筛选。日期按中国标准时间的业务发生日期计算，列表分页总数也使用相同条件。列表显示单号、来源、去向、箱码数量、条码预览、操作人和时间。点击销售出库单或仓库流转单，可查看本次流转周期的整单签收率、各项商品签收率以及每个箱码的待签收、已签收或异常状态。

需要汇总分批出库时，在流转单据列表中勾选至少两张普通单据后点击“合并所选”：

1. 销售出库单必须来源仓库和销售人员都相同。
2. 挪仓单必须来源仓库和目标仓库都相同。
3. 销售出库与挪仓不能混在一次合并中。
4. 合并后直接生成一张新的销售出库单或仓库流转单，原分批单从列表和详情中退出，不再单独显示或打开。
5. 条码流转不会重复生成，条码履历中的单号统一显示为合并后的新单号。
6. 合并操作不可拆分恢复；需要复核、查询、纠错或安全作废时都直接操作新出库单。
7. 新单时间取所选分批单中最晚的一张，日期筛选和列表排序也按该时间计算。
8. 单次可合并 2 至 20 张、最多 5000 个箱码；跨日期合并会再次提示。
9. 待复核单和已复核单可一起合并；新出库单会重新进入待复核，之前的复核版本仅在后台审计中保留。

### 8.3 勤策签收

显示同步任务、导入范围和处理结果。有效签收会自动：

1. 回填商品名称和单位。
2. 将当前归属改为勤策“收货单位名称”。
3. 将签收状态改为“已签收”。
4. 保留原销售人员出库或目标仓库挪仓履历。

重复导入同一日期或同一 Excel 不会重复生成签收事件。

## 9. 出库复核

1. 网页进入“出库复核”，查看待复核或已复核的出库单。
2. 出库提交后已经即时生效；复核只记录数量，不是放行审批。
3. 填写实际总出货数量，必须是包括 0 在内的非负整数。
4. 可选填各商品品类数量。实际总数、有效扫码数或品类合计不一致时页面会提示，但仍可保存。
5. 仓库管理员和超级管理员可首次复核；已复核记录只有超级管理员可以修订。
6. 每次修订生成新版本，详情中可查看全部历史。复核后若发生纠错或条码删除，详情会醒目标记。
7. 复核完成后，整单签收率使用最新复核的实际总出货数量计算，各商品签收率使用对应复核品类数量计算；页面会标注“复核口径 vN”。待复核和历史免复核单据仍使用箱码数量，并标注“条码口径”。
8. 品类数量未填满时会显示未分配数量；勤策识别出未填写数量的商品时会显示“待补充复核数量”。签收数量超过复核数量时比例可超过 100%，页面会标红提示，需由超级管理员修订复核数据。
9. 复核数量为 0 时签收率显示“—”，不会进行除零计算。

## 10. 勤策连接器

1. “仓库系统地址”是签收数据要上传到的网站。
2. “连接器密钥”用于证明上传请求来自已配置的连接器。
3. “保存配置”只保存地址和密钥。
4. “测试勤策”检查当前 Chrome 是否仍登录勤策并能读取扫码明细。
5. “检查并同步”立即领取待同步任务，按指定日期范围读取并上传。
6. 连接器每分钟检查一次任务；电脑关机时任务会保留，下次打开 Chrome 后补跑。

默认计划为每周一同步上一自然周。手动同步会补跑到当前时间，重叠日期由本系统内部去重。

## 11. 管理纠错与系统维护

### 11.1 条码与单据纠错

1. 超级管理员可在条码详情删除错误条码的档案、本地流转和单据关联；删除后相同条码可重新扫码建档。已有勤策签收记录或已经核销的条码禁止删除。
2. 超级管理员可在出库单详情纠正来源仓库、业务类型、销售人员或目标仓库。
3. 条码已有后续勤策签收、回库或再次出库时，系统会拒绝纠正或回滚删除原单。
4. 回滚删除会把已有条码恢复到出库前归属，并物理删除业务单；由该单首次创建且没有勤策记录的条码档案也会删除。
5. 本轮不支持回库单纠错。高风险操作均需二次确认，备注选填，操作日志会记录结果。

### 11.2 账号管理

超级管理员可编辑、启停和重置其他账号，系统始终保留至少一个启用的超级管理员。

### 11.3 操作日志

最近操作的动作、结果和说明以中文显示，便于核对是谁在何时完成了出库、回库、同步或资料维护。

### 11.4 健康和备份

健康检查显示网站和数据库是否可用。正式数据库按服务器计划备份并上传私有 OSS；备份不影响日常操作。

### 11.5 系统重置

超级管理员输入精确文字 `确定重置` 后才可执行。重置会清除业务、追踪、同步和基础资料数据，保留用户和角色，且不会写入测试数据。

## 12. 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 商品显示“待勤策补全” | 箱码尚未取得有效勤策签收，属于正常状态 |
| 条码无法出库 | 核对来源仓库；该条码可能已归属于其他仓库、销售人员或店铺 |
| 条码无法回库 | 条码已经在仓库时会被拒绝；跨仓请使用快速出库到仓库 |
| 勤策同步后仍是待签收 | 检查条码是否完全一致，并查看同步批次中的未匹配或异常说明 |
| 挪仓后由目标仓库直接送达 | 直接同步勤策签收即可；系统会从挪仓记录继续追踪，无需补录销售出库 |
| 同一码先后出现在两家店铺 | 当前归属按最新有效勤策扫码时间更新，两个签收事件都会保留 |
| 提交后网络中断 | 保留当前表单再次提交；系统不会因重试重复记录 |
| 实际总数与扫码数不一致 | 复核可以保存，详情会保留差异提示和当时的有效扫码数 |
| 错误条码无法删除 | 已有勤策签收记录或已经核销时禁止删除；其他情况由超级管理员在条码详情清理 |
| 页面显示数据库故障 | 暂停业务提交，恢复数据库后刷新页面 |
