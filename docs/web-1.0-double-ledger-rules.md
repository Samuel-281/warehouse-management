# Web 端 1.0 双账本业务规则

## 目标

Web 端 1.0 使用“数量库存 + 条码追踪”双账本：

- 仓库库存只回答“哪个仓库、哪种货物、当前还剩多少件”。
- 条码追踪只回答“这个已经扫码进入系统的条码，现在在哪里、经历过哪些流转”。

不要再把仓库库存理解为全部来自条码记录的汇总。

## 到货入库

厂家到货入库只填写仓库、货物和数量。

提交后：

- 仓库商品库存数量增加。
- 生成入库单和数量明细。
- 不创建条码记录。
- 不新增可追踪条码。

## 扫码出库

扫码出库是统一出库入口。操作员选择出库仓库、货物、去向类型和条码。

去向类型支持：

- 销售人员：来源仓库库存减少，条码归属变为销售人员。
- 仓库：来源仓库库存减少，目标仓库库存增加，条码归属变为目标仓库。

出库数量以扫码条码数量为准，不能超过来源仓库该货物当前库存。

如果扫码出库时条码不存在，系统会创建该条码的追踪档案。

## 退回入库

退回入库包含两个分支。

销售退回：

- 只选择退回仓库并扫码。
- 不手动选择销售人员。
- 系统通过条码当前归属自动识别原销售人员。
- 成功后仓库库存增加，条码归属变为仓库。

终端店铺退换货：

- 选择退回仓库、终端店铺、货物、数量、生产日期并扫码。
- 条码不存在时创建追踪档案。
- 条码在销售人员名下时自动回流仓库。
- 条码已在仓库时禁止重复入库。
- 如果条码已有生产日期且和本次填写不同，不阻断流程；条码档案保留原生产日期，本次填写日期记录在单据明细中。

## 首页与查询

首页分为两个核心区域：

- 左侧：各仓库货物储备，显示仓库商品库存数量。
- 右侧：可追踪条码，显示系统中已建档条码的数量、当前归属和流转入口。

查询页必须继续避免加载全量条码。库存数量、单据和条码详情都应使用分页或按需查询。
