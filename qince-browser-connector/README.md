# 勤策签收浏览器连接器

该连接器复用 Chrome 中已经登录的勤策会话，按仓库系统下发的明确起止日期读取扫码明细，并回传给仓库系统。它不保存勤策账号密码，也不需要 OpenID/AppKey。

## 工作方式

1. 仓库系统在每周一 00:00 创建“上一自然周”的待同步任务，或由用户点击“立即同步”创建任务。
2. 连接器每分钟检查一次待同步任务。
3. 连接器使用任务中的 `startDate` 和 `endDate` 查询勤策；不会使用“近 7 日”快捷选项。
4. 仓库系统按箱码、扫码时间、扫码人、收货单位生成唯一指纹，重叠日期或重复执行不会重复写入。
5. 电脑在周一关机时，任务会留在服务器；周三打开 Chrome 后仍补跑上周一至上周日。

## 本地验证配置

在 `warehouse-web/.env` 中增加：

```dotenv
QINCE_SYNC_MODE="browser_connector"
QINCE_BROWSER_CONNECTOR_TOKEN="请生成至少 32 位随机字符串"
```

重启 Web 程序后，在 Chrome 打开 `chrome://extensions/`，开启“开发者模式”，选择“加载已解压的扩展程序”，目录选择本文件夹。

连接器弹窗中填写：

- 仓库系统地址：本地测试使用 `http://localhost:3002`，正式服务器使用 `http://43.108.14.102`
- 连接器密钥：与服务器环境变量 `QINCE_BROWSER_CONNECTOR_TOKEN` 完全一致

首次使用先在 Chrome 登录勤策并打开“数字营销 / 扫码明细”，再点击连接器中的“测试勤策”。

## 正式服务器定时任务

服务器仍使用现有命令在每周一 00:00 创建任务：

```text
npm run terminal-receipts:sync-weekly
```

浏览器连接器负责领取任务和回传数据。Chrome 不在线不会导致日期窗口漂移，也不会丢失待同步任务。
